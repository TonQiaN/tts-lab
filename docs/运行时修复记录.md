# 本机 Index MLX 兼容性修复

日期：2026-11-05。环境：Apple M3 Max / 64 GB，macOS，Python 3.11.15，PyTorch 2.10.0。

原依赖锁中的 `mlx==0.31.1`、`mlx-metal==0.31.1` 在加载 IndexTTS 2.5、W2V-BERT 和 CAMPPlus 后崩溃，进程返回 `-11`。本机崩溃报告为 `EXC_BAD_ACCESS / SIGSEGV`，Python faulthandler 指向 `mlx.nn.Module.__setattr__`。保留了失败实验和日志。

关闭 S2Mel/BigVGAN compile 后仍能复现。随后只升级 MLX 与 MLX Metal 到 **0.32.4**，保持适配代码 commit、模型权重、Python 和 Torch 不变，同一参考、同一文本成功生成；IndexTTS 2 和 2.5 的共同对照随后均成功。该结果说明升级在当前环境中解决了已观察的崩溃，不对所有机器或其他 MLX 版本作泛化结论。

修复已保存到 `config/locks/mlx-indextts2.uv.lock`，安装脚本会恢复该锁。上游业务代码没有本地修改。Breeze 保持自己独立的 MLX 0.32.2 / Torch 2.9.1 环境。

另修复启动器停止后立即重启的竞争：停止命令等待本机健康端点关闭，再启动新进程。失败任务保留，不标记生成验证。后续生成日志开启 faulthandler 并显示进程退出码。

## 长文分段复测

173 字普通话长文在 Index 2.5 每段 100 token 时产生严重异常的自动转写。仅将文本分段上限降为 40 token，其余请求、参考、种子和模型保持一致后，转写恢复为接近原文，Whisper base 的归一化诊断 CER 从 0.9545 降到 0.0649。原结果和复测结果均保留，不将识别器差异当作人工确认的错读。

工作台 Index 2.5 默认已使用 40 token 分段；Index 2 保持 100。两者显式设置较宽的声学 token 上限，避免长段落沿用短句默认上限而提前截断。仍需对实际文本试听检查稳定性。
